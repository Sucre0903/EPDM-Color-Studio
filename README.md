# ZT Color Match Studio · EPDM Granule Mix Designer

从"配比计算程序"升级为"数字材料设计工作台"，包含两条互补的工作流：

- **工作台（自动解析）**：批量输入目标色（可自定义命名，每个目标色可
  单独设置锁定/排除颜色和点缀杂色）→ 点彩式光学混合求最优配比 → 逐个
  预览颗粒质感材料样板 → 一次性导出全部目标色的 Excel 配方表(工厂加工
  用) + 单张 SVG/PNG 材料样板(方案汇报/客户沟通用)。
- **手动配色（逆向工作区）**：直接指定色号+比例，或从工作台解析结果
  一键复制过来做微调，实时预览——满足经验配色、来料配色这类不需要
  （或不信任）算法自动求解的实际工作场景。

## 一键启动

**Windows 10 / 11 x64**：从 GitHub Release 选择 Lite 或 Full Offline，完整解压后双击
`start.bat`。Lite 在缺少 Python 或依赖时首次联网，Full Offline 随包提供初始化资源。
升级、迁移个人色库及历史记录、完全卸载可使用发行包内的维护入口。
详见 [Windows 安装说明](docs/OFFLINE_INSTALL.md)。

**Mac / Linux**：终端执行 `bash start.sh`。

开发者可参考 [发布与验收流程](docs/RELEASING.md)。

## 这一版做了什么（第七轮：配方模式 —— 推荐方案 / 方案探索）

### 配方模式（Recipe Mode）取代了原来的"推荐/偏深/偏亮"

之前的"偏深方案/偏亮方案"本质上只是同一个最优解调了调整体明暗，配色
结构（用了哪些颜色、几种颜色）基本没变，参考价值有限。这一版换成了
两种明确的配方模式：

- **推荐方案（Best Match，默认）**：只给 1 个最接近目标色的最优方案，
  适合日常快速使用；
- **方案探索（Explore）**：在色差可接受范围内，给最多 6 个配色结构有
  明显区别的方案——不同的颜色组合、不同的颜色数量、不同的主次比例结构，
  而不是同一批颜色的小调整。

Explore 模式用的是"多样性筛选"（Diversity Filtering）：算法本来就会
算出几十个候选组合再挑最优的一个，这一版直接复用这些已经算好的候选
（不重新搜索，不增加额外计算开销），用贪心最远点采样的方式，每一轮都
挑一个"和已经选中的方案们差异最大"的，保证挑出来的几个方案之间是真的
有区别，而不是凑数。

两种模式可以按目标色单独设置（跟锁定颜色/排除颜色/颜色数量一样，属于
"独立设置高级参数"的一部分），也可以在"全局默认高级设置"里统一设置。

Explore 模式挑出来的每一个方案，功能和推荐方案完全一样——都能选中当
前查看、看完整配比和预览、导出 PNG/SVG/Excel、收藏到历史记录、一键
复制到手动配色继续微调，不存在"只能预览不能用"的差别对待。

## 上一轮改动（第六轮：手动配色支持目标色参考 + 每色独立颜色数量）

### 1. 手动配色支持可选的目标色参考（优先级最高）

「手动配色」工作区里每个配方现在多了一个**可选**的"参考目标色"（取色器
+ HEX 双向同步，和目标色列表的取色器用法一致）：

- **不填**：还是纯手动预览工具，只看点彩混合效果，不做任何比较；
- **填了**：生成预览时会自动算出这次手动配比和参考目标色的 ΔE00 色差，
  并给出分档小标签方便一眼判断——

  | ΔE00 范围 | 标签 |
  |---|---|
  | < 3 | 优秀 Excellent |
  | 3 ~ 6 | 可接受 Acceptable |
  | > 6 | 建议调整 Needs Adjustment |

从工作台"复制过来"的配方会**自动带上原来的目标色**做参考（微调时天然
想知道离原来想要的颜色更近还是更远了）；"新建空白"的配方默认不填，
保持纯手动工具的定位不受影响。

### 2. 每个目标色的"颜色数量"也纳入独立设置

之前独立设置只覆盖锁定颜色/排除颜色/点缀杂色，颜色数量仍然是全局统一
的。这一版把颜色数量也加进了每个目标色的独立设置里——勾选"独立设置
高级参数"的目标色，可以单独指定自己用几种颜色（2~6），不再受左下角
全局默认颜色数量的限制。

## 上一轮改动（第五轮：交互性能 + 取色器 + 独立高级设置 + 手动配色）

### 1. 结果渲染做了缓存，操作不再卡顿（优先级最高）

之前只要对界面做任何操作（调整颜色数量、切换偏亮/偏深方案、点下载
按钮……），右侧的材料样板图和 SVG 都会重新渲染一遍——目标色一多，
每次操作都要重新跑一遍渲染，界面就会卡顿、白屏。

根源不是"重新解析配方"（生成配比的最优化计算本来就只在点「生成配比」
时才跑），而是材料预览图和 SVG **渲染本身**没有做缓存，任何页面重跑都
会把所有目标色的图重新画一遍。这一版把渲染函数用 `st.cache_data` 包了
起来，缓存 key 只取真正影响画面的参数（混合色/目标色/配比/材料/颗粒
尺度/随机种子）——只要这些没变，无论做什么其它操作，都会直接命中缓存，
不会重新计算。同时给最优化求解本身也加了缓存（额外保障：重复生成完全
相同的目标色不会重复计算）。

### 2. 目标色取色器

目标色现在支持两种输入方式：取色器（点击选色，HEX 输入框会自动同步
显示）和手动输入 HEX（输入合法的 HEX 也会反过来同步取色器的颜色块），
两者双向联动。屏幕取色（Eyedropper）需要额外做一个浏览器组件，工作量
和这次的改动不是一个量级，先没做——如果这个需求很关键，告诉我单独安排。

### 3. 每个目标色可以单独设置高级参数 + 新增"排除颜色"

目标色列表里每一项都有一个「独立设置高级参数」勾选项：

- 不勾选：使用下方"全局默认高级设置"（省心，适合大部分场景）；
- 勾选：单独指定这个目标色自己的锁定颜色 / 排除颜色 / 点缀杂色，不
  影响其它目标色。

同时新增了「排除颜色」（Exclude Colors）：指定的色号本次搜索完全不
考虑，等价于临时把它们从色库里拿掉（比如某个颗粒临时缺货）。排除和
锁定冲突时（同一个色号既被锁定又被排除），按锁定处理，并给出提示。

### 4. 新增"手动配色"工作区（Reverse Mix Workspace）

新增一个独立 Tab：直接指定色号和比例，实时看点彩式光学混合的效果——
不需要（或不信任）算法自动求解时用这个。支持：

- 从工作台的解析结果**一键复制**过来做微调（复制的是当前选中的方案，
  推荐/偏深/偏亮都可以）；
- 也可以「新建空白」从头开始，色号+比例一行一个地填（比例不需要凑够
  100，会自动按比例归一化）；
- 和工作台一致的导出能力：SVG / PNG 下载、收藏到历史记录、导出单条
  配方的 Excel。

## 上一轮改动（第四轮：批量处理 + 工厂交付）

### 1. 支持多目标色批量配比 + 自定义命名

左栏"目标色列表"改成一张可增删行的表格（`名称` + `目标色 HEX`），一次
可以填任意多个目标色，名称随便填——数字（1/2/3）、字母（A/B/C）、中文
名、英文名都行。点一次「生成配比」，后台按顺序对每一行分别算一次最优
配比（颜色数量、颗粒尺度、锁定颜色、点缀杂色这些参数在本次批量里统一
生效，不需要每个颜色单独设置一遍）。

右侧结果区按顺序给每个目标色一张独立的折叠卡片（标题就是"配方编号 ·
自定义名称 · HEX"），互不干扰；第一条默认展开，其余收起，避免颜色一多
就要没完没了地滚动。自定义名称会一路带到预览图文件名、Excel 配方表里，
不会在导出后变回一串没有意义的色号。

某一行 HEX 格式不对不会导致整批失败——会跳过那一行、报一条提示，其余
正常生成，这是"批量"该有的容错行为。

### 2. 成果输出拆成两部分

**材料预览图**（延续原有形式，做了两处改进）：
- 目标色/混合色色块从 62px 放大到 74px，图例文字从 16px 放大到 19px，
  画布宽度从 900px 放大到 980px，整体更接近一张可以直接打印查看、拿去
  给客户看的完整数字材料样板，而不是一张凑合能看的截图。
- SVG（矢量，可在 Illustrator/Figma 编辑文字）和 PNG（位图，快速分享）
  两种格式不变，每个目标色单独下载。

**Excel 配方表**（全新，工厂加工用，`excel_export.py`）：
- 一次点击导出**覆盖本次批量所有目标色**的一份 `.xlsx`，不用一个个色
  分别导出；
- 列：配方编号 / 目标色名称 / 目标色（色块）/ 目标色 HEX / 材料 / ΔE00 /
  配比色号 / 色号 HEX / 对应颜色块（色块）/ 配比比例；
- 目标色相关的列纵向合并成一格（同一配方内不用重复看到同一个名字），
  颜色相关的两处专门用 `openpyxl` 的单元格底色画色块，工厂人员核对色号
  时可以直接用眼睛比对色块，不用逐字核对色号；
- 隔行做了浅色底纹，方便扫视区分不同配方。

### 3. 精简配比数据：去掉所有重量(kg)信息

比例 + 总产量本来就能换算出重量，主界面和所有导出结果（预览图、SVG、
Excel、历史记录）里都不再重复展示"多少 kg"这件事，只保留比例。原来的
"总重量(kg)"输入框也从界面里拿掉了——如果工厂后续需要具体重量，按比例
乘总产量现算即可。

### 4. 软件更名为 ZT Color Match Studio

品牌名从 `FK Color Studio` 改为 `ZT Color Match Studio`（副标题
`EPDM Granule Mix Designer` 不变），只改了 `branding.py` 里的一个常量，
App 标题、页面头部、PNG/SVG 导出文件里的品牌信息会自动同步更新，不用
逐处手改。Logo 图形本身、配色系统都没有变。

> 提醒：这次改名只是软件里显示的名字，项目文件夹和代码仓库名字
> （`fk_color_matcher`）没有跟着改，避免破坏你现有的 GitHub 仓库路径；
> 如果也想改文件夹名字，告诉我，我可以一起处理。

## 上一轮改动（第三轮细节修复）

### 1. Logo 显示遮挡 bug + 精确度问题（根因都找到了）

**显示遮挡**：品牌头部被白色区域盖住一部分，根因是 Streamlit 自带的
顶部工具栏（汉堡菜单/Deploy 按钮那条，`fixed` 定位、白底、高层级）
悬浮在页面最上方，而上一版把 `.block-container` 的顶部留白改小了，
导致自定义品牌头部被这条默认工具栏部分遮挡。修复：既然工具已经有
自己的品牌头部，默认工具栏没有实际用途，直接用 CSS 隐藏
（`[data-testid="stHeader"] { display:none }`），从根上解决遮挡，
顺带也让页面更干净（不再有多余的默认菜单栏）。

**Logo 精确度**：之前是凭观察重新画的几何图形，比例和对角线方向其实
是**画反了**——用像素扫描精确测量参考图后发现，正确的形状应该是
「三角形顶点贴着横杠右下角、底边撑满整个宽度」，而不是我原来画的
「顶部撑满、左下角收成尖点」。索性不再靠重画博精确，改成**直接使用
张唐景观提供的原始 Logo 文件**：裁剪到精确边界框（像素扫描测出
`x:[16,263] y:[15,262]`，248×248 正方形，灰度 `RGB(150,150,150)`，
边角是锐角无圆角）、白底转透明，存成 `assets/logo.png`，App 头部和
导出文件的 SVG/PNG 都直接内嵌这份原始素材（和颗粒纹理内嵌位图是
同一种技术），保证比例、细节、颜色和原始文件完全一致，不存在解读
偏差的风险。

### 2. 材料预览区域放大

中栏（材料预览）宽度占比从 `1.65` 提到 `2.05`，画布原生渲染尺寸从
380px 提到 460px（不是简单拉伸模糊，是原生分辨率跟着放大），整体
布局更符合"预览是视觉中心，参数是辅助控制"的设计工具逻辑。

### 3. 颗粒尺度支持更细数值

滑块下限从 6px 降到 2px（步进从 2 改为 1，调节更精细），性能实测
2px 颗粒在放大后的画布上耗时约 0.9 秒，仍在可交互范围内。现在可以
在"近景颗粒细节"（40px）和"远景综合色感"（2px，模拟正常行走距离
看到的铺装完成面效果）之间自由切换，更贴近景观设计师的实际使用场景。

## 上一轮改动

### 1. 修复 SVG 导出打不开的问题（根因 + 修复）

之前导出的 SVG 文件在 Illustrator / Figma / 浏览器里报错打不开。根因是
`<image>` 标签用了 `xlink:href` 属性，但根 `<svg>` 节点没有声明
`xmlns:xlink` 命名空间，属于不合法 XML（`unbound prefix` 错误），
严格解析器一律拒绝打开（Streamlit 自带的宽松渲染器不报错，掩盖了问题）。

修复内容：
- 根节点补上 `xmlns:xlink="http://www.w3.org/1999/xlink"` 声明；
- `<image>` 同时提供 SVG2 标准的 `href` 和向后兼容的 `xlink:href`，双保险；
- 非渲染定义（`<clipPath>`）规范地放进 `<defs>`，更符合标准；
- **每次生成 SVG 后立即用严格 XML 解析器（`xml.dom.minidom`）自检**，
  格式有问题会在生成阶段就报错，不会把打不开的文件交付出去；
- 已用 `minidom` 和 `lxml` 两种解析器在多种场景（4 色/6 色、含锁定色、
  含点缀色）交叉验证，确认合法。

导出原则保持不变：颗粒质感部分是内嵌位图（保留随机纹理的真实感），
标题、Logo、色号、比例、图例全部是矢量 `<text>`/`<rect>`/`<polygon>`
元素，可在设计软件里直接选中文字编辑、缩放不失真。

### 2. 品牌视觉：Logo 标志 + 工作台命名

新增 `branding.py` 统一管理视觉规范，App 界面和导出文件共用同一套定义：

  "Z"意象），原创几何绘制，仅用图形符号，不含中文字样，参考张唐景观
  （Z+T Studio）的极简气质；
- **命名**：`FK Color Studio` / `EPDM GRANULE MIX DESIGNER`，替代原来的
  "FK配色程序"字样，弱化企业软件感；
- Logo 出现在 App 顶部头部，以及 PNG / SVG 导出文件的品牌头部区域，
  视觉统一。

### 3. 配比结果表：颜色优先，数据辅助

右侧配色方案面板改成色卡式列表（`render_palette_html`）：每行是
色块 + 色号（含点缀/锁定标记）+ HEX + 比例条 + 百分比 + 用量，色块和
比例条都用实际颜色填充，第一眼就能看出配色结构，不用逐字读色号。
原始数据表格仍保留在「查看数据表格」折叠面板里，方便复制导出。

### 4. 整体 UI：三栏工作台布局

参考 Adobe / Figma 的「工具栏 + 创作画布 + 属性面板」结构重新组织：

- **左栏（参数）**：目标色、总重量、材料、颜色数量、颗粒尺度等基础
  参数常驻；锁定颜色、点缀杂色等专业参数收进「高级设置」折叠面板；
- **中栏（材料预览）**：最大视觉区域留给颗粒质感大图，推荐/偏深/偏亮
  方案切换、下载和收藏都在图片下方，画布是视觉主体；
- **右栏（配色方案）**：目标色/混合色对照条 + 色卡列表 + ΔE 等关键数据。

配合 `.streamlit/config.toml` 主题（中性石墨灰替代默认红）和轻量 CSS
（品牌头部、色卡样式、留白间距），整体观感从"计算颜色比例的表格工具"
转向"创建数字材料样板的设计工具"。

  折叠面板里可以直接对比推荐/偏深/偏亮三个方案的色卡。

## 关于 UI 改造的坦诚说明

Streamlit 本质上是一个"用 Python 写数据应用"的框架，不是像 Figma /
Adobe XD 那样的像素级自由布局工具——它的表单控件（滑块、按钮、输入框）
有自己固定的外观，能通过官方主题（`.streamlit/config.toml`）调整配色，
也能通过注入 CSS 做进一步的精细化，但没法做到和专业设计软件完全一致
的视觉自由度和精致度。这一版已经把能做的都做了（主题、三栏布局、品牌
头部、色卡组件、折叠高级设置），效果会比之前"工程后台感"强很多，但
心理预期上它仍然是"一个专业感更强的 Streamlit 应用"，而不是一个原生
设计软件。如果后续想要更进一步的像素级自由度，会需要换成 React / 纯
前端框架重写界面层，那是另一个量级的工作。

## 核心算法（沿用前几版，未改动）

- **点彩式光学混合**（`color_utils.partitive_mix`）：线性光空间按颗粒
  面积占比加权平均，而非颜料式 sRGB 直接平均；
- **严格颜色数量 + 颜色锁定**：每色设最低比例下限，锁定色强制参与，
  超出数量上限自动扩容；
- **点缀杂色**：按目标明暗自动选浅色/深色点缀池中拟合损失最小的一个；
- **均衡交织颗粒分布**：蛇形空间序 + 配额亏欠贪心法，避免深色颗粒
  连续聚集成色斑（实测同色邻居比例降低约 39%）；
- **固定随机种子**：生成配比时锁定种子，避免无关交互导致预览图
  无缘无故重新随机排布。

详见各模块内的 docstring 和上一版 README 存档的算法细节。

## 已知局限

- **点彩式混合无法突破颗粒本身的色域**：若目标是高饱和色而色库缺对应
  高饱和颗粒，ΔE 会偏高，需要补充对应颗粒色号。
- **点缀/锁定颜色和色彩还原度存在真实的物理权衡**：这是预期行为，
  界面上会如实显示 ΔE 变化，不做隐藏。
- **UI 精致度受 Streamlit 框架本身限制**，见上文"坦诚说明"。
- **预览图为方向确认图**，颗粒质感为程序模拟效果，非最终实物照片。
